# 主流程：候选池流水线

> 全文不出现具体业务阈值，一律引用 `config/anchors.yaml`。
> 阶段标识符与 `scripts/pool.py` 的 `STAGES` 常量一一对应。

## 0. 总览

每个候选方向 = 一张**机会卡**（模板见 `assets/opportunity_card.md`）。
卡在十个阶段（Step 0–9）间推进，卡上始终带着它的证据、缺口和下一步动作。

```
Step 0 bounds       经营边界输入
Step 1 discovery    机会发现      ──▶ 池：10–20 张卡（定性，零数字）
Step 2 hard_filter  硬筛          ──▶ 池：5–8
Step 3 demand       需求验证      ──▶ 池：3–5
Step 4 competition  竞争验证+VOC  ──▶ 池：2–3
Step 5 deep_gate    深度闸门      ──▶ 池：1–2
Step 6 economics    经济测算      ──▶ 池：1
Step 7 priority     优先级矩阵    ──▶ 排序表
Step 8 test         小批实测      ──▶ Go / Iterate / No-Go
Step 9 retro        复盘回填      ──▶ 校准 anchors.yaml
```

## 1. 三条贯穿全程的硬规则

1. **未筛 ≠ 通过。** 任何阶段缺数据，标记为"未筛/缺失"，不得当作"通过"往下推。
2. **数字只能来自数据源或用户输入。** AI 的职责是提出假设、组织证据、暴露缺口，不是生产数字。
3. **"待补"不能写成"已通过"。** 报告再完整，缺口必须留在台面上。

## 2. 逐阶段定义

### Step 0 · bounds 经营边界输入

**进入条件**：用户提出选品需求。

**动作**：收集九项边界——

| 约束项 | 说明 |
|---|---|
| 目标站点 | 默认 US |
| 目标人群 | 使用场景、客群画像 |
| 售价区间 | 与 `anchors.yaml#hard_filters.price_band_usd` 对照 |
| 可投入资金 | 首单备货 + 推广预算上限 |
| 可承受试错损失 | 决定 No-Go 的止损线 |
| 包装尺寸与重量 | 影响头程与 FBA 成本结构 |
| 供应链优势 | 已有品类、工厂资源、开模能力 |
| 排除类目 | 带电、易碎、超大件、季节性等 |
| MOQ 范围 | 可接受最小起订量 |

**退出标准**：九项全部有值。

**异常**：用户给不全 → 填默认值并标 `assumed: true`，**不得静默假设**。

### Step 1 · discovery 机会发现

**进入条件**：边界已确认。

**动作**：两条分支。

- **分支 A（从零挖掘）**：让 AI 基于约束输出 15 个细分方向，只做定性描述。
  之后用 Helium 10 Black Box / 卖家精灵检索候选 niche，**并回亚马逊前台人工核验关键词真实性**。
- **分支 B（基于已有 ASIN/关键词拓品）**：划分两类赛道——
  **细分赛道（做深）**：同一供应链下的相近产品（如厨师刀 → 面包刀、剔骨刀），可复用模具与质检资源；
  **互补赛道（做广）**：同一买家购物篮可能加购的配套产品（如厨师刀 → 磨刀棒、刀座、磁性刀架），
  也是天然的广告流量入口与品牌矩阵搭建点。

**退出标准**：池内 10–20 张机会卡 v0。

**异常**：
- **本阶段 AI 不得输出任何数字。** 出现销量、搜索量等具体数值即视为编造，必须剔除。
- AI 给的关键词在前台搜不到对应商品 → 该方向作废或修正。

### Step 2 · hard_filter 硬筛

**进入条件**：池内有卡。

**动作**：逐条执行 `references/hard-filters.md` 的清单。每条是布尔判断，
**任一条命中即出局**。命中记录写入机会卡的 `hard_filter_hits`。

**退出标准**：池收敛到 5–8 张卡。

**异常**：**数据缺失 = 标"未筛"，绝不等于"通过"。** 见 `references/hard-filters.md` 第三节。

### Step 3 · demand 需求验证

**进入条件**：通过硬筛。

**动作**：回答需求四问。数据源优先官方（商机探测器），站外（Google Trends、
TikTok、Pinterest、Reddit）仅作补充。

| 维度 | 关注点 |
|---|---|
| 需求规模 | 关键词搜索量、类目月销量 |
| 需求趋势 | 过去 12–24 个月走势，而不是只看当下 |
| 需求稳定性 | 季节型 / 节日型 / 事件型 / 常年型 |
| 需求真实性 | 关键词搜出来，消费者实际点击和购买的是不是同一个产品 |

每个方向输出：支持证据、反对证据、缺失信息、下一步核验动作。

**退出标准**：池收敛到 3–5 个需求成立的方向。

**异常**：
- 历史数据不足 12 个月 → 写明实际覆盖区间。
- **不得把相近关键词的搜索量相加当作市场总需求**（关键词之间存在重叠）。

### Step 4 · competition 竞争验证 + VOC

**进入条件**：需求成立。

**动作**：四层验证。

| 层次 | 看什么 |
|---|---|
| 市场结构 | Top10/Top20 销量集中度、品牌垄断程度、新品存活占比 |
| 产品结构 | 售价区间、Rating、Review 体量、变体类别、核心属性 |
| 流量结构 | 核心关键词、自然位/广告位占比、流量是否集中在少数头部 ASIN |
| VOC | 好评、差评、Q&A、退货原因 |

同时做 **VOC 聚类**：按问题主题聚类，给出数量、样本比例、对应 ASIN 和简短证据；
区分产品缺陷、使用问题与描述误差；不能从评论推出的结论标为待验证。

再打 **痛点四维标签**：

| 标签 | 含义 | 不满足的后果 |
|---|---|---|
| Frequency | 发生频次 | 低频痛点投入产出比低 |
| Severity | 严重程度 | 不严重用户不愿付费 |
| Solvability | 能不能做出来 | 无法落地等于空谈 |
| Economics | 改后成本/物流/利润是否划算 | 商业不成立 |

**四项全部满足，才纳入改良方向。**

最后按 `references/scoring.md` 第五节，**至少使用 4 个命名分析范式中的 3 个**。

**退出标准**：池收敛到 2–3 个有进入窗口的方向。

**异常**：低评分高销量样本 → 先排查品牌背景、促销力度、变体结构，
不得直接推出"这个类目新品容易做"。

### Step 5 · deep_gate 深度闸门

**进入条件**：有进入窗口。**只对存活下来的 2–3 个做，不对全池做。**

**动作**：

① **合规与知识产权深查**
- 平台类目准入与审批要求
- 危险品 Hazmat / SDS 文件
- 强制认证：FCC / FDA / CPC / UL / Prop 65
- 商标检索：USPTO Trademark Search
- 发明与外观专利：USPTO Patent Center、Google Patents

② **供应链六问**（发工厂询价，逐项确认下列六项）：

| 序号 | 确认事项 |
|---|---|
| ① | 公模/半公模能否实现设想，是否必须开发私模 |
| ② | MOQ 与阶梯报价 |
| ③ | 打样费、模具费、包装费 |
| ④ | 产品净重、外箱尺寸重量 |
| ⑤ | 生产周期、补货周期、旺季产能上限 |
| ⑥ | 需要的检测报告与认证材料 |

**退出标准**：IP 无红牌 **且** 拿到六问报价单。

**异常**：**IP 拿不准 → 标"需专业复核"，AI 不得自行下合规结论。**
亚马逊品牌注册库（Brand Registry）只能作壁垒参考，**不能替代**官方商标专利检索。

### Step 6 · economics 经济测算

**进入条件**：六问报价到手。

**动作**：建可复算的单 SKU 模型。

完整成本清单：产品采购、包装、国内报关、头程、关税、Referral fee、
FBA 配送费、仓储费、入库配置（inbound placement / prep）、广告 PPC、
优惠券/促销、退货损耗、次品率。

用 `scripts/break_even_acos.py` 计算：

```
Break-even ACoS = 广告前贡献利润 ÷ 售价
```

输出三种情景（保守 / 基准 / 乐观）、未计费用清单、首批资金峰值与补货资金需求。

**退出标准**：收敛到 1 个 economics 成立的 SKU。

**异常**：
- 缺失项**不填零**，显式列出。
- 固定投入与单件摊销**不得重复扣**（如开模费已摊入单件，就不能再算一次总额）。

### Step 7 · priority 优先级矩阵

**进入条件**：有至少 1 个候选。

**动作**：按 `references/scoring.md` 打分，用 `scripts/pool.py rank` 横向排序。

**退出标准**：排序表 + 推荐结论。

**异常**：缺失权重超过 `anchors.yaml#scoring.refuse_total_above_missing_weight` 时
**拒绝输出总分**——这是正确行为，不是脚本坏了。补齐数据后重跑。

### Step 8 · test 小批实测

**进入条件**：财务模型成立。

**动作**：读取本轮广告、业务和退货报表，统一日期范围，标明归因口径及数据延迟。
观测 CTR、CVR、CPC、TACoS、搜索词质量、自然排名、退货率、Rating、Review、退货根因。

对照预先设定的广告预算、亏损上限、单件贡献利润和质量要求做判断。

**退出标准**：Go / Iterate / No-Go 三选一。

| 决策 | 含义 |
|---|---|
| Go | 指标达标，可以增加数量 |
| Iterate | 部分指标不达标，确认可修改产品/Listing/广告后复测 |
| No-Go | 市场表现不及预期，果断止损，拒绝加仓抢救亏损品 |

**异常**：**不存在通用阈值。** 所有阈值由 `scripts/break_even_acos.py` 算出的
Break-even ACoS 与自身目标利润反向设定。

### Step 9 · retro 复盘回填

**进入条件**：实测有结果。

**动作**：用真实成败回测 `anchors.yaml` 里的锚点——如果某个锚点无法把
成功品与失败品分开，它就是没有区分度的。更新 `calibrated` 与 `last_reviewed`。

**退出标准**：锚点被校准，下次更准。

**异常**：回测显示锚点分不开成败 → **如实记录，不硬调**。
硬调锚点去拟合历史，只会让你在下一次选品时更自信地犯错。

方法细节见 `references/calibration.md`。

## 3. 阶段跳转规则

- 可以跳到任意阶段，但**决策性结论必须回填前序证据**。
- **不得跳跃 Stage 2 与 Stage 5**——这两道闸门是流程的骨架。
- 从 Stage 7 发现所有候选都不达标 → 回到 Stage 1 重新挖掘，而不是降低 Stage 6 的标准。

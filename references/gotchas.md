# 避坑清单

> 全文不出现具体业务阈值，一律引用 `config/anchors.yaml`。

## 一、时效性坑（会过期，需定期复核）

| 坑 | 表现 | 解法 | 时效 |
|---|---|---|---|
| **评论阈值失效** | 仍在用"TOP10 平均评论数低于某值 = 蓝海" | 2026-02-12 变体评论拆分规则生效（2026-05-31 完全生效），单个 listing 评论数系统性下降，阈值系统性偏高 → **必须回前台抽样复核后重校准** | ⚠️ 2026 新增 |
| 第三方销量当真值 | 拿第三方工具的月销直接下结论 | 第三方销量都是估算值，业内普遍认为误差极大，**只用于排序和交叉验证** | 常驻 |
| 认证要求变化 | 按去年的认证清单备货 | 上架前重新核对类目审批页 | 常驻 |

## 二、常驻坑

| 坑 | 表现 | 解法 |
|---|---|---|
| **跳层操作** | 看着顺眼直接进货 | 每层过了才进下一层；Stage 2 与 Stage 5 不可跳 |
| **未筛当通过** | 数据没拿到就当这条筛子过了 | 标 `unscreened`，在 Stage 5 必须补上，否则不能进入 Stage 6 |
| 低分高销 = 好做 | 看到评分低但销量高的品就冲 | 先排查品牌背景、促销力度、变体结构 |
| 搜索量相加当需求 | 把近义关键词的搜索量加总 | 关键词之间存在重叠，**不可加总** |
| **高频差评 = 机会** | 看到买家抱怨就改产品 | 过痛点四维；Economics 不过就砍。例：买家抱怨收纳盒不够大，你做大之后头程、FBA 费、破损率可能一起涨——消费者希望、商业上不值得 |
| 品牌库当 IP 检索 | 用 Brand Registry 替代 USPTO | 品牌注册库只能作壁垒参考 |
| 私模谈"小批量验证" | 以为能小单试私模 | 开私模费用高、MOQ 门槛高，"小批量验证"在私模面前不成立 |
| **尺寸差一点点** | 忽略包装尺寸 | 亚马逊对尺寸重量极敏感；包装尺寸变化会改变 FBA 成本结构，须重新测算 |
| 利润测算拍脑袋 | 转化率预估虚高 | 用市场真实转化数据校准 |
| **成本漏项** | 漏算退货、次品、促销、开模费 | 建完整成本清单；开模费必须进模型或明确单列，不能留在模型外 |
| 重复扣费 | 固定投入既摊到单件又算总额 | 固定投入与单件摊销**不得重复扣** |
| 缺失填零 | 没查到的成本当 0 算 | 缺失项**不填零**，显式列出 |
| **沉没成本救品** | 亏了加仓想翻本 | 预设决策线，到线就砍，**测品预算亏完就停** |
| 硬条件放水 | "这个品重但利润高" | 边界条件没商量 |
| AI 素材未标注 | 直接用 AI 生成的商品图 | 按平台要求标注 AI 生成 |
| **报告好看就当通过** | 把"待补"写成"已通过" | 缺口必须留在台面上；质量校验是把关用的 |

## 三、输出前必做的质量校验

打印或誊抄这一段，逐条打勾。**任何一条打不上勾，报告不得交付。**

```
□ 每个数字都有「来源 + 统计周期」？
□ 官方数据与第三方估算是否分开标注？
□ 有没有跨口径混算（不同站点/周期/产品口径直接比较）？
□ 缺失项是否标为"未筛"，而不是悄悄当成"通过"？
□ 评分是否声明了"基于 N/M 维"？
□ 是否使用了未校准锚点？用了是否打了 ⚠️ 标？
□ 有没有把"待补"写成"已通过"？
```

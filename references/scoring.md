# 评分口径与公式（Stage 7 优先级矩阵）

> 全文不出现任何具体阈值。所有数值一律取 `config/anchors.yaml` 的对应键。

## 一、为什么要有这套公式

选品评分最常见的失效方式不是算错，而是**每次口径都不一样**——今天用 A 标准挑出这个品，
下个月用 B 标准挑出那个品，两次结果无法比较，复盘也就无从谈起。

本评分只保证两件事：

1. **算术是确定的**——同一个候选、同一份锚点，算出来永远是同一个分。
2. **锚点是诚实的**——每个锚点都写明依据和是否校准。没校准就标出来，不冒充行业标准。

至于锚点选得对不对，那是你的生意经验，不是公式能解决的。

## 二、归一化公式

```
单指标得分 = clamp( (f(实际值) − f(锚点下限)) / (f(锚点上限) − f(锚点下限)), 0, 1 )
维度得分   = (该维度下所有拿得到的指标得分取平均) × 维度权重
总分       = Σ(各维度得分) ÷ Σ(实际参与计算的维度权重) × 100
```

### 2.1 方向（`direction`）

- `higher`：值越大越好。区间上界得满分，下界得 0 分。
- `lower`：值越小越好。**区间下界得满分，上界得 0 分**。

`lower` 用于 MOQ、TOP10 平均评论数、类目平均评分、FBA 卖家数、生产周期、认证项数、
IP 红牌数这类"越小越好"的**评分指标**。见
`anchors.yaml#scoring.dimensions.supply.metrics.moq`、
`anchors.yaml#scoring.dimensions.compliance.metrics.ip_red_flag_count`。

> 别和硬筛混淆：退货率、品牌垄断度是 Stage 2 的**硬筛阈值**（命中即出局），
> 见 `references/hard-filters.md`，它们不参与评分维度。

> 这是最容易写反的地方：MOQ 越低必须得分越高。

### 2.2 变换（`transform`）

- `log`：先取以 10 为底的对数再归一化。用于搜索量、销量、评论数、MOQ 这类
  **量级跨度可达数个数量级**的指标。不做 log 变换的话，区间上界的微小波动会把整个区间压扁。
- `none`：直接用原值。

零值在 `log` 下取 `log10(1) = 0`，不会报错。

## 三、缺失数据规则（本 skill 最重要的一条）

现实里你几乎不可能第一次就把所有数据拿齐。规则如下：

| 情况 | 处理 |
|---|---|
| 维度内部分指标缺失 | 用拿到的指标求平均，该维度照常计分 |
| **整个维度一个指标都没有** | **丢弃该维度，分母重归一化**——总分只除以实际算得出的维度权重 |
| **缺失维度权重占比 严格大于 熔断线** | **拒绝输出总分**，只输出已算出的分项 |

熔断线取 `anchors.yaml#scoring.refuse_total_above_missing_weight`。

### 3.1 为什么是"丢弃 + 重归一化"，而不是"缺失填零"

填零等于把"我没查到"谎报成"这个品在这一维很差"，会系统性压低分数，
让所有数据不全的候选看起来都很糟——这不是在评估产品，是在评估你的数据收集进度。

### 3.2 强制声明

任何一次评分都必须带 `declaration` 字段，形如 `本评分基于 4/5 维`。
**报告里必须原样展示这句话。** 看到 `3/5 维` 就知道这个分只用了三个维度，
不能和一份 `5/5 维` 的分直接比较。

### 3.3 熔断不是失败

拒绝出总分是**正确行为**，不是脚本坏了。它的意思是：
"你现在缺的数据太多了，这个分数给出来会误导你下单。"
补齐数据后重跑即可。

## 四、未校准锚点

`anchors.yaml` 里每条锚点都有 `calibrated` 字段。**所有未校准（`calibrated: false`）的
评分锚点**都会出现在评分结果的 `uncalibrated_anchors` 列表里——它由锚点配置算出，
与本次候选是否用到某个指标无关。

**规则：只要这个列表非空，报告结论必须打 ⚠️ 标并注明
"基于未校准的示例锚点，未按你的类目验证"。**

校准方法见 `references/calibration.md`。

## 五、四个命名分析范式（至少用 3 个）

分数只回答"排第几"，不回答"为什么"。出报告时必须配合分析范式：

1. **数据 → 空白 → 机会**：先摆数据，指出结构性空白，再落到机会点。
2. **痛点 → 优势映射**：把 VOC 里的痛点逐条映射到"我们能提供什么"。
3. **交叉维度 → 结构性空白**：两个维度交叉（如"高需求 × 低评分"）找出被忽视的格子。
4. **多维评估 → 优先级矩阵**：即本节这套加权评分，用于横向排序。

每份报告至少用 3 个。只用第 4 个（纯打分）不算合格——那只给了排序，没给理由。

## 六、权重怎么调

五维权重写在 `anchors.yaml#scoring.dimensions.<维度名>.weight`，合计必须为 100
（`tests/test_anchors.py` 会校验）。

建议：**先跑一遍，别急着调。** 权重只有在你有 3 个以上可比较的候选时才谈得上有意义。

# 逐阶段提示词库

> 每个阶段一组提示词，可直接复制。模板里出现数值时一律引用 `config/anchors.yaml`，
> **不要**在提示词里写死数字——锚点改了，提示词不用改。

## 使用说明

- 模板中的 `{占位符}` 必须替换为真实参数。
- **每组的「约束卡」不得删除。** 它们是防幻觉的关键，也是各阶段的边界。
- 提示词里"标注来源、区分口径、不补造"的条款不得删除。

---

## Step 0 · bounds 经营边界输入

```
我是一名亚马逊卖家，请按以下经营边界协助选品：
目标站点：{US/UK/DE...}
目标人群：{使用场景、客群画像}
研究方向：{品类或关键词}
售价区间：{区间}
可投入资金：{金额}
可承受试错损失：{金额}
包装尺寸与重量：{已知则填，未知写"待定"}
供应链优势：{已有品类、工厂资源、可做的调整}
排除类目：{带电、易碎、超大件、明显季节性}
MOQ 范围：{区间}
目标：寻找需求相对稳定、存在可验证改进空间的细分方向。
先检查可用的选品数据工具及参数，再制定查询步骤。
区分能直接筛选的条件和需要人工核验的条件。
数据不足时明确标注，不要补造。
```

**约束卡**
- 九项边界缺项时，必须显式标 `assumed: true` 并说明假设值，**不得静默假设**。
- 本阶段不产出候选方向。

## Step 1 · discovery 机会发现

```
你是一名亚马逊选品分析师。请基于上述约束，输出 15 个细分品类方向：
①目标人群与使用场景；②未被满足的核心痛点；③产品形态与改良设想；④差异化方向。
每个方向 100 字左右。
```

**约束卡（本阶段最重要的一条）**
- **不得输出任何数字。** 不许写搜索量、销量、评论数、BSR、增长率——哪怕标注"估算"也不行。
  本阶段只做定性方向发散，数字一律留到 Step 3 由数据源提供。
- AI 给出的关键词必须回亚马逊前台人工核验：搜得到对应商品才算数，搜不到则该方向作废或修正。
- 不推荐具体爆款 ASIN。

### 分支：基于现有 ASIN / 关键词拓品

```
请基于 {关键词/ASIN}，输出 20 个相关方向，划分为两类赛道：
- 细分赛道（做深）：同一供应链下的相近产品，可复用模具与质检资源
- 互补赛道（做广）：同一批买家购物篮可能加购的配套产品，是天然的广告流量入口
每个方向说明与现有产品的关系。同样不要输出任何数字。
```

## Step 2 · hard_filter 硬筛

```
请对以下候选方向逐条核对硬筛清单，清单项与判据见 references/hard-filters.md，
具体阈值以 config/anchors.yaml 的 hard_filters 段为准——不要自行设定阈值。
对每一条给出三值结论之一：命中(hit) / 通过(pass) / 未筛(unscreened)。
拿不到数据的一律标 unscreened，不要推测。最后列出所有 unscreened 项。
```

**约束卡**
- **未筛 ≠ 通过。** 拿不到数据就标 `unscreened`，让它留在台面上。
- 不得用"大概率没问题"这类措辞填补缺失数据。

---

## Step 3 · demand 需求验证

```
对这批候选产品统一站点、统计周期和产品口径，分别检查：
买家搜索意图、购买信号、过去 12 个月趋势及价格促销变化。
标注哪些是官方数据、哪些是第三方估算，估算值给出估算方法。
每个方向输出：支持证据、反对证据、缺失信息、下一步核验动作。
历史不足 12 个月时写明实际覆盖区间。
不要把相近关键词的搜索量相加当作市场总需求——关键词之间存在重叠。
```

**约束卡**
- 每个数字必须带「来源 + 统计周期」，缺一不可。
- 官方数据与第三方估算必须分开标注。
- 反对证据必须输出，**不得只列支持证据**。

---

## Step 4 · competition 竞争验证 + VOC

```
①每个方向选取头部标杆和近期上架的可比竞品，说明选样理由。
按独立产品或父体口径比较价格、评分数、变体、促销及关键词表现。
对低评分高销量样本排查品牌背景、促销力度与变体结构。
只根据已获取样本判断，输出进入条件和最可能失败的原因。

②基于这些评论正文，按问题主题聚类，给出数量、样本比例、对应 ASIN 和简短证据。
区分产品缺陷、使用问题与描述误差。
每项建议写频次、影响、可行方案、成本风险及样品验收方式。
不能从评论推出的结论，标为待验证。

③对每个痛点打四维标签：Frequency / Severity / Solvability / Economics。
四项是否全部满足？未全满足的明确说明哪一项不满足。

④按 references/scoring.md 第五节的四个命名分析范式，至少使用其中 3 个来组织结论。
```

**约束卡**
- 低评分高销量样本**不得**直接推出"这个类目新品容易做"。
- 痛点四维未全部满足的，**不得**纳入改良方向。
- 评论里推不出的结论标"待验证"，不得当作事实。

---

## Step 5 · deep_gate 深度闸门

> 只对存活下来的 2–3 个方向做，不对全池做。

```
请核查以下候选品类在 {站点} 的合规要求：
1) 平台类目准入与审批要求
2) 是否需要危险品 Hazmat / SDS 文件
3) 是否涉及强制认证（FCC/FDA/CPC/UL/Prop 65）
4) 商标与专利检索建议（USPTO Trademark Search / Patent Center / Google Patents）
只输出可核实的信息，无法确认的标注"需专业复核"。
注意：亚马逊品牌注册库只能作壁垒参考，不能替代官方商标专利检索。
```

```
请整理一份发给工厂的询价清单，包含 6 项核心信息：
①公模/半公模是否可实现设想，是否必须开发私模
②MOQ 和阶梯报价
③打样费、模具费、包装费用
④产品净重、外箱尺寸重量
⑤生产周期、补货周期、旺季产能上限
⑥产品需要的检测报告、认证材料
并为每一项补充"为什么关键"的说明，便于和工厂高效沟通。
```

**约束卡**
- **AI 不得自行下合规结论。** IP 拿不准就标"需专业复核"，由人去找专业意见。
- 不得用"应该没专利问题"这类措辞替代实际检索。

## Step 6 · economics 经济测算

```
根据报价、实测包装参数和官方费用，建立可复算的单 SKU 模型：
- 分别计算广告前贡献利润、广告后贡献利润与固定费用后利润
- 广告统一按每件分摊或 TACoS 测算，另列简化盈亏平衡 ACoS
- 输出三种情景（保守/基准/乐观）、未计费用、首批资金峰值和补货资金需求
缺失项不填零；固定投入与单件摊销不得重复扣。
计算结果用 scripts/break_even_acos.py 复算一遍。
```

**约束卡**
- **缺失项不填零**，显式列进"未计费用清单"。
- 固定投入与单件摊销**不得重复扣**。
- 本阶段不引入任何阈值，判定线来自 `anchors.yaml`。

---

## Step 7 · priority 优先级矩阵

```
请对候选按 references/scoring.md 的归一化公式打分，阈值一律读 config/anchors.yaml。
输出每个维度的分项分、总分，以及"本评分基于 N/M 维"的声明。
缺失的维度直接丢弃并重归一化，不要填零冒充低分。
哪些锚点标了 calibrated: false？如使用了未校准锚点，在结论处加 ⚠️ 标注。
```

**约束卡**
- 必须输出"本评分基于 N/M 维"。
- 用了未校准锚点必须打 ⚠️ 标，**不得**把未校准锚点的结论当既定事实。
- 缺失权重超限时拒绝出总分是**正确行为**，不要为了"给个数"而凑数。

---

## Step 8 · test 小批实测

```
读取本轮广告、业务和退货报表，统一日期范围，标明归因口径及数据延迟。
对照预先设定的广告预算、亏损上限、单件贡献利润和质量要求，
判断是继续加量、调整复测还是停止。
每个结论给出证据、缺失项，以及下轮只改的一个主要变量。
止损阈值请用 scripts/break_even_acos.py 算出的盈亏平衡 ACoS 反推，不要套用别的类目的数。
```

**约束卡**
- **不存在通用阈值。** 判定线由自身 Break-even ACoS 与目标利润反推。
- No-Go 就是止损，**不得**因沉没成本而加仓抢救。

## Step 9 · retro 复盘回填

```
我有 N 个已完成选品的案例，结果已知（赚钱/亏钱/打平）。
请用 config/anchors.yaml 的现值对它们逐个打分，然后回答：
1) 分数能不能把成功品与失败品分开？
2) 哪些锚点没有区分度？
3) 如果分不开，是锚点选错了还是区间定错了？
如实说明。如果分不开就直说分不开，不要为了给出结论而硬调锚点。
```

**约束卡**
- 案例不足 3 个时，明确说明样本量不足，**不得**给出校准结论。
- **硬调锚点去拟合历史是被禁止的**——那只会让人在下一次更自信地犯错。

---

## 通用防幻觉条款（每组提示词都应保留）

```
- 每个数字标注来源与统计周期
- 区分官方数据与第三方估算
- 同时输出支持证据与反对证据
- 缺失信息显式列出，标注"未核/未筛"，禁止补造
- 结论必须能被给出的证据支撑
```
